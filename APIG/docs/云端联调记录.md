APIG 作业的基础链路已经完成：

- `yingteng-camera-support` Agent Runtime 已创建并处于 `Ready`，当前生效版本为 8。
- HTTP 转 MCP 服务 `yingteng_camera_http_mcp_v2` 已就绪，直接 MCP 握手和 `tools/list` 可返回 5 个摄像头工具。
- MCP 工具集 `yingteng_camera_toolset` 已核对为 `Mode=AllTools`（全量返回），工具集控制面清单包含 5 个工具；不是语义检索工具集。

### 2026-08-16：公网存量 API 与本地 Web 数据比对

- HTTP 转 MCP 服务的上游为受 API Key 保护的公网 API 网关，MCP 出站身份凭据使用 `yingteng_camera_runtime_api_key`。
- 只读调用云端 MCP 后确认其服务标识为“影腾摄像头管理 API v1.0.0”，并返回本地同样的 5 个工具。
- 对 CAM-003 进行列表、告警与诊断比对：摄像头状态、两条告警、丢包率 38.4%、延迟 486ms、网络异常结论及处置建议均与本地 Web API 一致。
- 结论：云端已有与本地实现一致的存量 API 部署；当前仍须将 Web 的数据访问统一切换到该公网后端，且 API Key 不可下发至浏览器。

### 2026-08-16：模型网关与 Web Runtime 调用验证

- 原 Runtime 请求返回模型网关认证失败；已仅替换 Runtime 的 `MODEL_AGENT_API_KEY` 为模型网关的 `lmt_test` Proxy API Key，并发布版本 8。
- `agentkit invoke` 最小问答已成功，验证 Runtime 经模型网关可用。
- 本地 Web 后端初次调用失败原因为 Python 默认 CA 证书链不信任企业网络证书；已改为使用受信任 CA 包，保持 HTTPS 证书校验，不采用关闭校验的绕过方式。
- `/api/agent/chat` 已返回 200；“你是谁？”请求已获得 Runtime 的真实回答。Runtime 调用密钥只存在于本地服务进程环境中，未写入项目文件。

### 当前云端异常

Runtime 通过工具集公网地址握手时，实际 `tools/list` 仍只返回平台包装工具 `mcp_search_tool` / `mcp_use_tool`；调用包装工具时返回上游 URL 为空（`unsupported protocol scheme ""`），导致搜索结果为 `null`，Agent 尚不能调用 5 个摄像头工具。

已做的只读/低风险核对：

- 控制面 API：`Mode=AllTools`，`ListMCPToolsetTools` 返回 5 个工具且 `IsAllTool=true`。
- HTTP 转 MCP 直连：初始化成功，直接 `tools/list` 返回 5 个工具。
- Runtime：绑定字段指向 `yingteng_camera_toolset`，版本 7 为 `Ready`。
- 同工具集重新挂载、同服务配置刷新均未消除工具集内部上游 URL 为空的问题。
- 临时探测工具集已创建并清理，未替换现有工具集，也未修改 API 文件。

结论：当前阻塞在 AgentKit MCP 工具集到 HTTP 转 MCP 服务的运行时路由，而不是 OpenAPI、HTTP 转 MCP 工具定义、工具集模式或 Agent 代码。需要平台侧刷新/修复该工具集的上游路由，或由控制台重新创建一个可正常发布的 AllTools 工具集后再绑定 Runtime。
