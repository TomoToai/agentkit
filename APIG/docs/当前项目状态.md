## 控制台登录态（浏览器前门鉴权，2026-08-20，最新）

### 目标

- 保留鉴权（用户明确要求「鉴权一定要做」），同时让 Web 控制台能在浏览器里直接打开。
- 网关级 static `key_auth` 要求每个请求头带 `Authorization: Bearer`，浏览器加载页面无法自动携带，前门必然 401——这不是页面/后端 bug，是网关鉴权发生在 `server.py` 之前。

### 方案（已实现，已部署）

- 改由**应用自身管理登录态**：多用户账号密码 → 服务端 PBKDF2（20 万次迭代、加盐）校验 → 签发 **HttpOnly + SameSite=Lax + Secure + HMAC 签名** 的无状态会话 Cookie（无需服务端存储，兼容 FaaS 多实例）。
- `server.py` 新增：`issue_session_token`/`verify_session_token`（HMAC-SHA256 签名 token）、`_load_console_users`/`_verify_password`（PBKDF2 校验，支持 `pbkdf2$` 哈希串或明文兜底）、`_require_api_authorized`（/api/* 统一闸门）、`/login` 页、`/api/login`·`/api/logout`·`/api/session` 接口。
- **前门规则**：未登录访问任意控制台页/`/api/*` → 302 跳 `/login` 或 401 `login_required`；`/health`·`/login`·登录登出接口公开。
- **另外两层鉴权原封不动**：业务 API 的 `X-API-Key`（机器/MCP 直连仍可用，`_require_api_authorized` 保留 key 分支）、Agent Runtime 的 `key_auth`（`invoke_agent_runtime` 服务端持 Bearer key）。密码/密钥均不下发浏览器、不进 Git、不进审计日志。
- 新增 `static/login.html`（独立登录页）+ `server.py` 内联兜底登录页；`index.html` 加「退出登录」按钮，`app.js` 加登出逻辑。
- 环境变量：`CONSOLE_USERS`（`账号:pbkdf2$...` 分号分隔）、`CONSOLE_SESSION_SECRET`（会话签名密钥）、`CONSOLE_SESSION_TTL_SECONDS`（默认 12h）。云上通过 `runtime_envs` 注入真实值（PBKDF2 哈希，非明文）。

### 「记住我」免登录（2026-08-20 追加）

## Web 前端“乱码”修复：SSE 解析 + Runtime 对接更正（2026-08-20）

### 现象

- 云上 Web 控制台「摄像头诊断助手」气泡里直接铺满 `data: {"modelVersion":...,"thought":true,...}` 原始事件流（含模型思考 token），页面看似“样式错乱”。

### 根因（三处叠加，均在 Web 后端 `server.py`，前端 `static/app.js` 无需改动）

1. **SSE 未解析**：Runtime 改为 WebServer App 后 `/invoke`·`/run_sse` 返回 ADK SSE 事件流，而 `server.py` 仍按单 JSON 解析失败 → 把整段 SSE 原文回吐给前端，`app.js` 原样渲染。
2. **端点过期**：`AGENT_RUNTIME_URL` 指向 8/13 已废弃的旧 Runtime `r-yesqnzaps0wkn7ohev1d`（域名 `s70hbg...` 已 NXDOMAIN）。当前正确 Runtime `r-yesysnbwg065mv4cfb77` 端点为 `s4erjj70ad5nbo374vhu6...`。
3. **调用方式过期 + 密钥失效**：旧代码用 `POST /invoke {"prompt":...}`；WebServer App 正确方式是先建 session 再 `POST /run_sse`（camelCase：`appName/userId/sessionId/newMessage`），session 已存在返回 409 需幂等忽略。API Key 也需换用 `agentkit runtime show --json` 中的当前值。

### 修复内容（`server.py`）

- 新增 `parse_sse_agent_response()`：解析 `data:` 事件、**过滤 `thought:true` 思考分片**、聚合 `content.parts[].text` 为干净答复；保留旧 JSON/纯文本回退。
- 重写 `invoke_agent_runtime()`：`_runtime_base_url()` 归一化基地址；先幂等建 session（409 视为复用），再 `POST /run_sse`；`AGENT_RUNTIME_APP_NAME` 默认 `yingteng_camera_support`。

### 云端部署（关键教训）

- **两份独立服务**：出问题的是云上 Web 应用 `yingteng-camera-web`（非本地 `127.0.0.1:8000`，也非 diagnosis Runtime）。本地热修不影响云端，必须重新部署 Web 应用。
- **CLI 升级破坏兼容**：`agentkit` 从 0.50.x 自升级到 **0.52.5**，配置从旧扁平格式改为 `common/launch_types` 新嵌套格式；命令从 `deploy build/apply` 拆成独立 `build` + `deploy`。旧 yaml 备份为 `.agentkit/agentkit.yaml.flat-bak`，新配置写在项目根 `APIG/agentkit.yaml`。
