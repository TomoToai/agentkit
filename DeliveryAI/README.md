# DeliveryAI Demo 工作空间

> 基于火山引擎 AgentKit **DeliveryAI（交付官）** 的客户 Demo 素材仓库。

## 概述

DeliveryAI 是由多 Agent 协作驱动的研发交付工作空间。需求创建后自动关联流程，各节点由 Agent 自动执行，人工仅在关键决策或异常节点介入确认。

### 三大角色
| 角色 | 使用端 | 核心职责 |
|---|---|---|
| **企业管理员** | 火山控制台（管理端） | 开通服务、SSO 配置、模型/沙箱模板、企业集成 |
| **空间管理员** | 独立客户端（用户端） | 创建空间、配置流程/Agent/Skill/MCP、添加成员 |
| **空间成员** | 独立客户端（用户端） | 个人授权、处理需求、人工确认节点 |

## 典型 Demo 演示路径

### 🎯 Demo 1：端到端需求交付自动化（推荐首选）
> 面向使用飞书项目 + CodeBase 的研发团队，展示"需求→代码→上线"全自动链路

1. 空间管理员展示空间配置（流程绑定、Agent 模板、Skill）
2. 在飞书项目使用指定流程模板创建一条 Demo 需求（如"新增用户登录页面"）
3. 需求自动同步至 DeliveryAI，依次经过：
   - **需求澄清节点**：Agent 生成结构化确认卡片 → 人工确认
   - **Spec 设计节点**：Agent 产出 Spec 文档 → 人工确认
   - **编码实现节点**：Agent 在 CodeBase 创建分支、提交代码
   - **联调测试节点**：Agent 生成测试报告、截图证据
   - **MR 节点**：Agent 创建 MR，关联代码哈希
   - **发布节点**：Agent 生成发布报告、健康检查结果
4. 展示需求详情面板的"证据链"：跨节点集中查阅所有产物

### 🎯 Demo 2：Agent 角色标准化沉淀
> 面向希望复用 Agent 配置的团队，展示角色模板的创建与绑定

1. 在 Agent 配置中展示系统内置模板（需求分析师、Coder、Tester）
2. 演示如何基于内置模板复制 → 微调系统提示词 → 绑定自定义 Skill/MCP
3. 将模板绑定到流程节点，形成"节点 = 角色"映射
4. 在多个需求上验证同一角色的行为一致性

### 🎯 Demo 3：存量流程渐进式落地
> 面向已有成熟流程的团队，展示低风险接入路径

1. 导入示例流程，先启用少量 AI 节点（如仅需求澄清 + Spec 设计）
2. 其余节点保留人工处理，在小范围 Demo 需求上验收
3. 逐步把更多节点切换为 AI 执行
4. 完成上线前验收清单的逐条核对

## 快速开始

1. **企业管理员**：参考 `docs/setup-guide.md` 完成控制台侧企业级配置
2. **空间管理员**：下载客户端 → 创建空间 → 参考 `flows/templates/` 导入流程 → 参考 `agents/templates/` 配置 Agent → 添加成员
3. **空间成员**：登录客户端 → 完成个人授权 → 在飞书项目创建需求开始体验
