# Demo 场景 1：端到端需求交付自动化

> **受众**：使用飞书项目 + CodeBase，希望打通「需求→代码→上线」全自动链路的研发团队。

## Demo 目标
1. 展示需求从飞书项目创建后，如何自动进入 DeliveryAI 流转
2. 展示各节点 Agent 的执行效果与人工确认交互
3. 展示完整的交付证据链（Spec、代码、测试、MR、发布报告）

## 演示前置检查清单
- [ ] 企业管理员已完成控制台配置（SSO、模型、沙箱、集成）
- [ ] 空间管理员已创建空间、绑定飞书项目 + CodeBase、导入流程模板
- [ ] 空间成员已完成个人授权（飞书项目 + CodeBase）
- [ ] 飞书项目中存在已绑定的流程模板，且可正常创建需求
- [ ] CodeBase 目标仓库可正常读写，基准分支设置正确
- [ ] 沙箱模板健康检查通过（可手动触发一次沙箱验证）

## 演示剧本（预计 15~20 分钟）

### Step 1：环境与空间展示（2 min）
1. 登录 DeliveryAI 客户端，展示空间首页
2. 进入空间「设置」，快速展示：
   - 已绑定的飞书项目需求空间
   - 已绑定的 CodeBase 仓库与基准分支
   - 已配置的流程模板列表
3. 进入「Agent 配置」，展示已绑定的 5 类 Agent 模板（需求分析师/Spec设计师/Coder/测试/发布）

### Step 2：在飞书项目创建需求（2 min）
1. 切换到飞书项目管理系统
2. 使用**已绑定 DeliveryAI 的流程模板**创建一条需求，示例：
   - **标题**：「新增用户登录页面（手机号+验证码）」
   - **描述**：
     > **用户故事**：作为未登录用户，我希望通过手机号+验证码方式登录，以便无需记忆密码。
     >
     > **验收标准（AC）**：
     > 1. 手机号输入框支持 11 位校验，格式错误实时提示
     > 2. 点击「获取验证码」后倒计时 60s，验证码有效时间 5min
     > 3. 登录成功后跳转到用户首页，显示欢迎语
     > 4. 登录失败（手机号未注册/验证码错误）给出明确错误提示
   - **优先级**：P2
   - **负责人**：当前演示成员
3. 保存需求，记录需求 ID

### Step 3：回到 DeliveryAI 观察自动流转（8~12 min）
1. 切换到 DeliveryAI 客户端「需求中心」，确认 Step 2 创建的需求已出现
2. 点击进入需求详情，展示「时间线」视图

#### 节点 1：需求澄清（Agent 执行 + 人工确认）
- **Agent 动作**：需求分析师 Agent 读取项目地图、架构、相关代码，生成结构化确认卡片
  - 需求范围：是否包含"忘记密码"等相邻功能？
  - 技术栈：前端 Vue3 + TS，后端 ... （自动识别）
  - 接口依赖：是否需要新增/复用验证码发送接口？
- **人工操作**：演示者逐项确认，提交
- **产出证据**：《需求澄清确认单.md》

#### 节点 2：Spec 设计（Agent 执行 + 人工确认）
- **Agent 动作**：Spec 设计师 Agent 产出详细设计文档
  - 页面原型描述（文字版）
  - API 契约（请求/响应 JSON Schema）
  - 数据模型变更
  - 测试用例清单
- **人工操作**：演示者检查后确认
- **产出证据**：《Spec 设计文档.md》、API 契约文件

#### 节点 3：编码实现（Agent 自动执行）
- **Agent 动作**：Coding Agent 在 CodeBase
  - 基于基准分支创建 feature 分支：`feat/demo-login-<需求ID>`
  - 按 Spec 提交代码，自动生成 commit message
  - 触发本地构建与单测
- **人工操作**：无需操作，自动推进
- **产出证据**：分支名称、Commit 哈希列表、构建日志、单测报告

#### 节点 4：联调测试（Agent 自动执行）
- **Agent 动作**：测试 Agent
  - 基于测试用例清单生成并执行自动化测试脚本
  - 截取桌面端/移动端页面截图
  - 产出测试报告（通过率、失败用例详情）
- **人工操作**：如无严重失败则自动推进，失败则回退到编码节点
- **产出证据**：测试报告、UI 截图、覆盖率统计

#### 节点 5：MR 创建（Agent 自动执行 + 可选人工 Review）
- **Agent 动作**：Agent 在 CodeBase 创建 MR
  - MR 标题自动关联需求 ID
  - MR 描述包含：Spec 摘要、变更文件列表、测试结果摘要
  - 自动设置 Reviewer（可按空间配置规则）
- **人工操作**：演示者快速浏览 MR diff，点击 Approve
- **产出证据**：MR 链接、Review 状态

#### 节点 6：正式环境发布（Agent 自动执行 + 人工确认）
- **Agent 动作**：发布 Agent
  - 合并 MR 到基准分支
  - 触发 CI/CD Pipeline
  - 执行发布后健康检查（接口探测、页面可访问性）
  - 生成发布报告
- **人工操作**：演示者检查健康检查结果，确认发布成功
- **产出证据**：CI 日志、发布版本号、健康检查报告、发布公告

### Step 4：展示交付证据链（3 min）
1. 在需求详情面板切换「需求详情 / Spec 文档 / 文件」三个标签
2. **需求详情**：展示状态流转时间线，每个节点的执行摘要
3. **Spec 文档**：展示节点 2 产出的完整 Spec
4. **文件**：展示所有附件证据（截图、报告、日志、代码哈希链接）
5. 切回飞书项目，展示需求状态已同步更新为"已完成"，并带有 DeliveryAI 回写的交付摘要

## Demo 后客户常见问题 FAQ
1. **Q: 代码质量如何保证？Agent 写的代码能直接上线吗？**
   A: 流程中 MR 节点默认要求人工 Review，同时可接入静态扫描、安全扫描作为自动门禁。
2. **Q: Agent 执行出错了怎么办？**
   A: 节点支持「回退到上一节点」「重新执行当前节点」「转为人工处理」三种容错策略。
3. **Q: 现有流程与 DeliveryAI 不一致，可以改吗？**
   A: 支持。参考 Demo 场景 3（渐进式落地），可先少量 AI 节点接入，再逐步调整。
4. **Q: 成本如何？**
   A: 主要由三部分构成：模型调用费用（火山方舟）、沙箱运行费用（按实例时长）、AgentKit 服务费用（按量/包年）。具体联系客户经理。
