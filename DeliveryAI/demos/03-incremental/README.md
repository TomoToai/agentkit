# Demo 场景 3：存量流程渐进式落地

> **受众**：已有成熟研发流程（飞书项目 + CodeBase + CI/CD），希望低风险、小步引入 AI 交付能力的团队。

## Demo 目标
1. 展示"先接入示例流程、再逐步扩展节点"的稳妥接入路径
2. 对比全人工流程 vs 半 AI 流程 vs 全 AI 流程的效率差异
3. 展示上线前验收清单，确保生产化前链路可靠

## 渐进式落地路线图
```
阶段 0: 诊断    → 梳理现有流程节点，标记适合 AI 接管的候选节点
阶段 1: 观察    → 导入示例流程，仅启用 1~2 个低风险 AI 节点（如需求澄清 + Spec）
阶段 2: 扩展    → 逐步把编码、测试、MR、发布节点切换为 AI
阶段 3: 优化    → 引入自定义 Agent、Skill/MCP，针对团队实际场景优化
阶段 4: 生产化  → 完成上线前验收清单，正式在业务线推广
```

## 演示剧本（预计 12 分钟）

### Step 1：诊断阶段 — 候选节点识别（2 min）
1. 打开飞书项目现有工作流截图，逐一讨论节点：
   | 节点 | 适合 AI？ | 原因 |
   |---|---|---|
   | 需求录入 | ❌ | 人工输入源头 |
   | 需求澄清 | ✅ 高 | 有代码上下文，可结构化输出确认卡片 |
   | Spec 设计 | ✅ 高 | 基于澄清结果可标准化产出 |
   | 技术评审 | ⚠️ 中 | 可 AI 初评 + 人工终评 |
   | 编码实现 | ✅ 高 | 核心 AI 节点，配合人工 Review |
   | 代码评审 | ⚠️ 中 | Agent 辅助 CR，人工拍板 |
   | 测试 | ✅ 高 | 自动化用例生成 + 执行 |
   | 发布 | ✅ 高 | 固定步骤，可编排自动化 |

### Step 2：阶段 1 — 半 AI 流程（仅需求澄清 + Spec）（4 min）
1. 导入示例流程，除「需求澄清」「Spec 设计」为 AI 节点外，其余全部设为**人工节点**
2. 创建一条 Demo 需求，跑完两个 AI 节点后，手动点击完成其余人工节点
3. 展示：即使只启用 2 个 AI 节点，也能获得结构化的澄清单 + Spec 文档，为后续人工节点提供输入规范

### Step 3：阶段 2 — 扩展到编码 + 测试（3 min）
1. 编辑流程，把「编码实现」「联调测试」两个节点也切换为 AI
2. 创建第二条 Demo 需求，对比阶段 1 和阶段 2 的：
   - 人工介入次数（阶段 1 需人工处理 5 个节点 → 阶段 2 只剩 2 个）
   - 总耗时对比
   - 证据完整性对比

### Step 4：阶段 4 — 上线前验收清单（3 min）
展示上线前验收清单，逐项核对：
- [x] 企业级 SSO、模型、沙箱模板全部配置完成
- [x] 至少 2 条 Demo 需求完成端到端（阶段 2 级别）跑通
- [x] 每条需求的节点证据链完整（Spec/代码/测试/MR/报告）
- [x] 人工确认节点交互流畅，无明显阻塞性文案问题
- [x] Agent 输出规范符合团队格式要求（代码风格/文档模板）
- [x] 飞书项目状态回写双向同步无误
- [x] CodeBase 分支命名/Commit 规范/MR 模板符合团队要求
- [x] 沙箱健康检查连续 3 次通过，无偶发性超时
- [x] 空间管理员 + 至少 2 名空间成员培训完成
- [x] 异常回退机制验证通过（模拟节点失败 → 回退/重跑/转人工）
