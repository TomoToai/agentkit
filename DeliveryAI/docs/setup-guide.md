# DeliveryAI 配置接入指南

> 按角色分工的分步操作手册，**严格按顺序执行**。

---

## 第一阶段：企业管理员配置（火山引擎控制台）

### 前置条件
- 已联系客户经理开通 DeliveryAI 邀测权限
- 持有火山引擎主账号（或具有管理员权限的子账号）

### 1.1 开通服务
1. 登录 [火山引擎 AgentKit 控制台](https://console.volcengine.com/agentkit/)
2. 进入「交付官」入口，确认服务状态为"已开通"

### 1.2 配置 SSO 认证与用户
1. 进入「用户管理」→ 配置企业 SSO（对接企业身份系统）
2. 导入或创建用户账号，划分：
   - 空间管理员权限
   - 空间成员权限

### 1.3 配置模型
1. 进入「模型管理」→ 绑定火山方舟可用模型（推荐 Doubao 2.0 Pro 系列）
2. 设置模型调用额度与空间可见范围

### 1.4 配置沙箱模板
1. 进入「沙箱模板管理」→ 创建沙箱模板
2. 配置基础镜像、Python/Node 版本、预装依赖
3. 保存模板（创建模板不计费，流程运行时才计费）

### 1.5 配置企业集成
| 集成项 | 说明 |
|---|---|
| 飞书项目 | 配置 App ID / App Secret，绑定需求空间 |
| CodeBase | 配置 Personal Access Token，绑定代码仓库组织 |
| 消息通知 | 配置飞书机器人 Webhook（可选） |

### 1.6 分发客户端入口
完成以上配置后，将「用户端下载链接」分发给空间管理员。

## 第二阶段：空间管理员配置（DeliveryAI 客户端）

### 2.1 安装并登录
1. 使用企业管理员分发的链接下载桌面客户端
2. 通过 SSO 账号登录

### 2.2 创建产品空间
1. 点击「新建空间」
2. 填写空间名称（如"XX 团队研发交付空间"）
3. 选择所属业务线

### 2.3 绑定集成资源
进入空间「设置」→「集成」：
1. **飞书项目**：选择需求空间 → 选择工作流模板 → 设置基准分支与标签规则
2. **CodeBase**：选择代码仓库 → 设置基准分支（如 `main`/`master`）

### 2.4 导入流程模板
参考 `../flows/templates/` 中的示例，在空间「流程管理」中：
1. 导入示例流程 JSON
2. 启用流程，设置为"空间默认流程"
3. 逐个节点检查 Agent 绑定是否正确

### 2.5 配置 Agent 模板
参考 `../agents/templates/` 中的角色模板：
1. 进入「Agent 配置」
2. 基于系统内置模板创建自定义 Agent：
   - 需求分析师 Agent
   - Spec 设计师 Agent
   - Coding Agent
   - 测试 Agent
   - 发布 Agent
3. 为每个 Agent 绑定：模型、系统提示词、Skills、MCP 工具

### 2.6 添加空间成员
进入「成员管理」→ 邀请团队成员（通过 SSO 账号搜索），分配角色：
- 空间管理员（少量）
- 空间成员（研发/测试/产品等）

## 第三阶段：空间成员准备（DeliveryAI 客户端）

### 3.1 个人授权
登录客户端后，进入「个人中心」：
1. 完成飞书项目个人授权（用于以成员身份操作需求）
2. 完成 CodeBase 个人授权（用于以成员身份提交代码、创建 MR）
3. 配置个人消息通知 Bot（可选）

### 3.2 个人配置（可选）
在「个人设置」中可覆盖：
- 个人专属 Agent 模板
- 个人 Skill / MCP 配置
- 按产品空间覆盖流程配置

> **注意**：个人配置仅对自己生效，不影响空间默认配置和其他成员。

---

## 第四阶段：创建 Demo 需求验收

1. 在**飞书项目**中使用绑定的流程模板创建一条需求
2. 回到 DeliveryAI 客户端「需求中心」，确认需求已自动同步
3. 观察需求状态流转，处理人工确认节点
4. 在需求详情面板检查各节点证据（Spec、代码、测试报告、截图、MR、CI 等）
5. 完成端到端验收后，参考 `demos/01-end-to-end/` 下的验收清单

## ❌ 常见反模式

| 问题 | 后果 | 正确做法 |
|---|---|---|
| 先发放客户端入口，后做企业级配置 | 空间管理员无法正常登录/创建空间 | 严格按「企业→空间→成员」顺序 |
| 混合勾选多种 AI Span 类型（同回流评测） | 同一 Trace 产生重复噪声样本 | 仅保留 `agent` 类型 |
| 需求描述无验收标准（仅"优化一下页面"） | Agent 无法判断范围与完成标准 | 先规范需求描述格式，含验收 AC |
| 一次性把所有节点切换为 AI | 流程不稳定，人工返工成本高 | 渐进式：先 2-3 个 AI 节点，跑通后再扩展 |
