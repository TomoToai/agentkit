# STS 是什么

> Security Token Service(安全令牌服务)速览
> 整理自 veops-cli 安装过程中关于鉴权方式的讨论。

## 一句话理解

STS = **Security Token Service(安全令牌服务)**,是云厂商(火山引擎、AWS、阿里云都有)提供的一种发放**临时、有时效访问凭证**的机制。

它不是让你一直用那对"永久钥匙"(AK/SK),而是**临时借你一把有效期几小时、到点自动作废的钥匙**去访问云资源。

## 它和永久 AK/SK 的区别

| | 永久凭证 | STS 临时凭证 |
|---|---|---|
| 组成 | AccessKey + SecretKey(2 个) | AccessKey + SecretKey + **SecurityToken**(3 个) |
| 有效期 | 长期,除非手动删除/轮换 | 短期,如 15 分钟 ~ 48 小时,**到点自动失效** |
| 来源 | 火山控制台创建、长期保存 | 由 STS 服务临时签发 |
| 泄漏后果 | 严重——一直有效,能长期被滥用 | 较轻——很快过期,危害窗口小 |

## 工作原理:拿长期身份换短期令牌

你(或某个角色)先证明身份,STS 就发给你一份带时效的临时三件套;程序拿这份临时凭证去调云 API,过期了再换一份新的。

好处很直接:

- **降低泄漏风险** —— 临时凭证即使被人拿到,很快就作废;
- **不用到处散布长期 AK/SK** —— 尤其在容器、CI、给别人临时授权等场景;
- **可精细授权** —— 签发时能限定这份临时凭证只能干哪些事、能用多久。

## 对应到 veops-cli 的两种鉴权方式

- **AK/SK 环境变量**:用的是**永久凭证**(项目 `.env` 里那对)。简单直接,适合本机开发,但要注意别把 `.env` 提交进 Git。
- **`veops-cli login`(OAuth)**:拿到的是 **48h STS 临时凭证**,会带一个 SecurityToken、到期自动失效,存到 `~/.volcengine/config.json`。长期密钥不落在到处都是的地方,更安全。
